# UI 원칙

화면을 새로 만들거나 고칠 때 이 순서로 확인한다. 위에 있을수록 우선한다.

## 1. 구조

1. **레이아웃 안정성** — 조작으로 요소가 나타나거나 사라져 다른 요소가 밀리지 않게 한다 (CLS와 같은 문제의식).
2. **숨기지 말고 비활성으로** — 지금 쓸 수 없는 동작도 같은 자리에 흐리게 둔다. 할 수 있는 일이 늘 보이고, 손이 위치를 기억한다.
3. **고정 하단 액션 바** — 주 동작은 화면 하단 한 곳에 둔다. 엄지가 닿고, 스크롤해도 같은 자리다.
4. **상태는 같은 자리에서 바꾼다** — 요소를 더하지 말고 같은 슬롯의 문구·색을 바꾼다. 슬롯은 한 줄 높이로 고정, 넘치면 줄임표.
5. **화면 한 장 (앱 셸)** — 페이지는 스크롤하지 않고, 스크롤은 콘텐츠 영역 하나에만 둔다. 헤더는 `AppShell` 하나로 통일.

## 2. 문구 (토스·당근 방식)

- **해요체 한 가지.** 회원·관리자 화면 모두. "~합니다/됩니다"는 쓰지 않는다.
- **구체적으로.** "곧" 대신 "11월 30일(월) 21:00", "많이" 대신 숫자.
- **버튼은 동사.** "예약하기", "충전하기". 비활성 버튼에는 무엇이 빠졌는지 적는다 ("시간을 골라주세요").
- **군더더기 없이.** 이모지·괄호 덧붙임·가운뎃점(·) 나열을 줄인다. 한 문장이 길면 두 문장으로.
- **차이가 있을 때만 말한다.** 막대·색이 이미 보여주는 값("빈 19h")을 글자로 반복하지 않는다. 기본 상태는 조용히, 예외만 표시.
- **빈 상태에도 다음 행동을.** "아직 없어요" 다음에 무엇을 하면 되는지.

## 3. 숫자·날짜 형식

| 쓰임 | 형식 | 함수 |
|---|---|---|
| 날짜(제목·목록) | 11월 2일 (월) | `formatDateKo` |
| 시각(기록·일정) | 11/30 21:00 | `formatDateTime` |
| 시간 구간 | 14~17시 | `summarizeHours` |
| 기한 | 2/1까지 | `formatExpiry` |
| 금액 | 40,000원 | `formatPrice` |

`toLocaleString()`을 그대로 쓰지 않는다 (초까지 나오고 브라우저마다 다르다).

## 4. 타이포그래피

`text-2xs`(11px)가 하한이다. 임의 크기(`text-[10px]`)는 안내 그림 속 축소 화면에만 쓴다.

| 단계 | 클래스 | 쓰임 |
|---|---|---|
| 큰 숫자 | `text-4xl~5xl` bold | 보유 토큰 등 화면의 주인공 하나 |
| 화면 제목 | `text-lg` semibold | 섹션·모달 제목 |
| 본문 | `text-sm` | 대부분의 내용 |
| 보조 | `text-xs` `text-ink-muted` | 설명, 메타 정보 |
| 최소 | `text-2xs` | 범례, 칸 안 라벨 |

숫자는 `tabular-nums`로 자리를 맞춘다.

## 5. 색

색은 모두 `index.css`의 토큰을 거친다 (다크 모드가 값만 바꿔 따라온다). 헥스 값을 직접 쓰지 않는다.

- `sage` — 주 동작, 내 예약, 선택됨. 한 화면에 진한 sage 버튼은 하나.
- `danger` — 되돌릴 수 없는 동작(취소·삭제)과 오류에만.
- `amber` — 기다리는 상태(입금 대기 등).
- `ink-muted` / `ink-faint` — 보조 정보. 중요한 숫자에는 쓰지 않는다.
- 색만으로 구분하지 않는다. 텍스트·패턴·위치를 함께 쓴다.

## 6. 면과 간격

- 카드는 `.card`(둥근 모서리 2xl, 얇은 선) 하나. 카드 안에 또 카드·테두리를 겹치지 않는다. 구분은 `divide-y`나 여백으로.
- 간격은 4의 배수: 요소 사이 `gap-2~3`, 섹션 사이 `space-y-5`, 카드 안쪽 `p-4~5`.
- 아이콘은 선 굵기 1.8의 단색 SVG(`currentColor`). 이모지를 아이콘 대신 쓰지 않는다.

## 7. 피드백과 접근성

- 누르는 곳은 44px 이상 (`min-h-[44px]`). 버튼은 `.btn-primary / -secondary / -ghost / -danger`만 쓴다.
- 처리 중에는 버튼을 비활성으로 두고 문구를 바꾼다 ("저장 중…").
- 결과는 화면 위쪽 토스트로 알린다. 오류는 `role="alert"`.
- 키보드 포커스는 전역 `:focus-visible` 링. 아이콘 버튼과 글자 없는 입력에는 `aria-label`.
- 모달은 공통 `ModalOverlay`(Escape, 포커스 가두기, 배경 스크롤 잠금).
- 움직임은 짧게(120~200ms), `prefers-reduced-motion`을 지킨다.

## 적용 예
- 예약 화면 하단 바: 선택이 없어도 항상 있다 (선택 0 → 비활성 "예약하기", 선택 → 활성, 취소 선택 → 빨간 취소 버튼). 안내/오류/환불 예상은 같은 한 줄 슬롯에.
- 관리자 일정표의 "회원 이름으로 등록" 영역도 선택이 없을 때 비활성으로 항상 보인다.
- 월 달력: 빈 시간은 막대로만 보여주고 글자는 다 찬 날의 "마감"만. 폰에서 내 예약 칩은 시작 시각("14시")만.
