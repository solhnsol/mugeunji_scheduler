# UI 원칙 (예약 화면에서 적용)

1. **레이아웃 안정성 (Layout stability)** — 사용자의 조작으로 요소가 나타나거나 사라져 다른 요소가 밀리지 않게 한다. 웹 성능 지표 CLS(누적 레이아웃 이동)와 같은 문제의식이다.
2. **숨기지 말고 비활성으로 (Disable, don't hide)** — 지금 쓸 수 없는 동작도 같은 자리에 흐리게 둔다. 사용자는 "무엇을 할 수 있는지"를 항상 볼 수 있고(인식 > 기억), 위치 학습(근접·위치 일관성, Fitts의 법칙)이 유지된다.
3. **영구 액션 영역 (Persistent action bar)** — 주 동작은 화면 하단의 고정된 한 곳에 둔다 (모바일 앱의 하단 앱 바/툴바 관례). 엄지 영역에 있고, 스크롤해도 같은 자리다.
4. **상태는 같은 자리에서 바꾼다 (Visibility of system status)** — 상태 변화는 요소를 추가하는 대신 같은 슬롯의 문구·색을 바꿔 알린다. 슬롯은 한 줄 높이로 고정하고 넘치면 줄임표.
5. **화면 한 장에 맞춘다 (앱 셸)** — 페이지 자체는 스크롤하지 않고, 스크롤은 콘텐츠 영역 하나에만 둔다.

## 적용
- 예약 화면 하단 바: 선택이 없어도 항상 존재 (선택 0 → 비활성 "예약하기", 선택 → 활성, 취소 선택 → 빨간 취소 버튼). 높이·위치 고정, 안내/오류/환불 예상은 같은 한 줄 슬롯에 표시.
- 관리자 일정표의 "회원 이름으로 등록" 영역도 선택이 없을 때 비활성으로 항상 표시.
