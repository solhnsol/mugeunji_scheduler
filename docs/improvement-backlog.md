# 기능 개선 후보 목록 (사용 편의성, 기능 위주)

**진행 상황 (2026-10-12)**: 4(입금 안내 표시), 6(비밀번호 6자 통일), 7(공개 규칙 조회), 19(중복 요청 경고), 23(로그인 후 원래 화면 복귀), 31(핵심 흐름 테스트)은 반영했다. 16(부족 토큰→충전 링크)은 이미 예약 화면에 있었다. 나머지는 알림·외부 연동·운영 결정이 필요해 보류.

> 2026-10 점검. UI/UX(디자인·레이아웃)는 별도 세션에서 다루므로 제외했다. 우선순위는 **12월 토큰 예약 정식 시작**을 기준으로 한 값이다. 번호는 우선순위가 아니라 참조용.

## A. 12월 전에 하면 좋은 것 (혼란·운영 부담을 직접 줄임)
1. **충전 요청 알림 (관리자)** — 회원이 충전을 요청해도 관리자는 탭을 열어봐야 안다. 요청이 들어오면 푸시/카톡/이메일 중 하나로 알려주면 "조금만 기다려 주세요" 시간이 줄어든다.
2. **입금 확인 후 회원 알림** — 토큰이 지급되면 회원이 알 방법이 없다(홈에서 직접 확인). 지급 시 문자/알림 또는 최소한 홈의 "새로 지급됨" 표시.
3. **입금 알림 자동 확인 웹훅** — 이미 `confirm_purchase(..., 'auto')` 훅이 있어 단축어→웹훅만 붙이면 된다. 기다림의 가장 큰 원인 제거.
4. **충전 요청 시 입금 정보 즉시 표시** — 지금은 "연락처로 안내"만 한다. 관리자가 설정한 `payment_guide`(계좌 등)를 요청 직후 화면에 보여주면 연락 왕복이 없어진다. (토큰 화면에서는 아직 노출 안 됨, 홈의 요금제 카드에서만 쓰임)
5. **셀프 비밀번호 재설정** — 지금은 오픈채팅으로 사람에게 요청해야 한다. 임시 비밀번호를 관리자 화면 외에 회원이 요청(→ 관리자 승인 큐)하게 하거나, 전화번호 인증 기반 재설정.
6. **가입 입력 검증 일치** — 서버 비밀번호 최소 4자 / 화면 6자로 서로 다르다. 아이디 중복은 제출해야 알 수 있다(입력 중 중복 확인).
7. **시간대별 토큰·환불 규칙의 공개 조회** — 랜딩·가입 전에는 규칙 숫자를 못 본다(로그인 후 예약 화면에서만). 읽기 전용 공개 엔드포인트(`/tokens/rules`)를 두면 랜딩이 관리자 설정과 항상 일치하게 숫자를 보여줄 수 있다. 지금 랜딩은 어긋남을 피하려 숫자를 뺐다.
8. **전환 시점 안내 자동화** — 랜딩 상단 안내(`ModeNotice`)와 가입 안내가 `reservation_mode`로 바뀌는데, 베타→토큰 전환 때 기존 월 신청 회원에게 남은 요금제/월 신청 화면·메뉴가 어떻게 정리되는지 점검 필요(요금제 변경·중단 메뉴, 시작 가이드).

## B. 예약 흐름
9. **터치 끌어서 선택** — 문서에도 남은 과제. 폰에서 연속 시간 선택이 탭 반복이라 번거롭다(길게 눌러 시작).
10. **반복 예약(매주 같은 요일·시간)** — 월 신청이 사라지면 고정 이용자가 매번 다시 골라야 한다. "이 시간 N주 반복" 일괄 예약 + 토큰 부족 시 가능한 만큼만 예약.
11. **같은 칸 경쟁 시 즉시 피드백** — 선택 후 다른 사람이 먼저 예약하면 실패 메시지만 뜬다. 실패한 칸만 표시하고 나머지는 유지.
12. **예약 확인 화면 / 영수증** — 예약 직후 "무엇을 몇 토큰으로" 요약과 취소 가능 시한 안내.
13. **일정 내보내기(.ics)·캘린더 연동** — 내 예약을 폰 캘린더에 추가.
14. **예약 리마인더** — 이용 N시간 전 알림(노쇼·무단 지각 감소).
15. **취소·환불 규칙을 선택 시점에 표시** — 취소 직전에야 환불 예상이 나온다. 예약 확정 전에 "이 예약은 ~까지 100% 환불" 안내.
16. **토큰 부족 시 바로 충전 연결** — "토큰이 n개 부족해요" 옆에 충전 화면 링크와 부족분에 맞는 상품 추천.
17. **지난/미래 내 예약 목록** — 홈은 앞으로 예약 5건만 보인다. 전체·지난 내역(사용 이력)과 월별 사용량.

## C. 토큰·결제
18. **만료 임박 알림** — 3개월 소멸이므로 "7일 후 n토큰 소멸"을 홈과 알림으로.
19. **충전 요청 중복·실수 방지** — 대기 중 요청이 있는데 또 요청하면 경고, 대기 건 수정(상품 변경).
20. **영수증/거래 내역 내보내기** — 충전·사용 내역 CSV 또는 월별 요약.
21. **상품 추천/자동 선택** — "이번 달 예상 사용량" 입력 → 적합한 상품 제안.

## D. 계정·안내
22. **연락처 변경 시 확인** — 연락처가 곧 입금 안내 채널인데, 잘못 입력해도 확인 수단이 없다(문자 인증 또는 관리자 확인 표시).
23. **로그인 상태·세션 만료 처리** — 30일 만료 후 예약 중 요청이 실패하면 입력이 날아간다. 만료 시 로그인 후 원래 화면 복귀(`next` 파라미터).
24. **공지 읽음 표시/새 글 알림** — 중요한 공지(규칙 변경)를 놓치지 않게 홈에서 미확인 공지 강조.
25. **오류 메시지 정리** — 서버 메시지가 구(舊) 방식 용어("월 신청")를 쓰는 곳이 남아 있는지 12월 전 일괄 점검.

## E. 관리자
26. **대기 중 충전 요청 일괄 확인** — 여러 건을 체크해 한 번에 확정.
27. **회원 검색/필터 (토큰 잔액, 최근 이용, 소멸 예정)** — 연락·정산 작업용.
28. **감사 로그** — 누가 언제 토큰을 조정·강제 예약/취소했는지 한 화면에서 조회.
29. **백업/복원 자동화** — SQLite 일일 백업과 복원 절차 문서화.

## F. 안정성
30. **서버 규칙 변경 시 화면 캐시 갱신** — 설정(토큰 비용·환불)이 바뀌면 열려 있는 예약 화면에 즉시 반영(웹소켓으로 이미 예약 변경은 전파됨).
31. **E2E 테스트** — 가입 → 충전 요청 → 확정 → 예약 → 취소 환불 핵심 흐름 자동 테스트(현재 백엔드 단위 테스트 중심).

## G. 점검 결과 (보안·안정성, 2026-10-12)
고친 것
- `/ws`가 로그인 없이 모든 예약(회원 이름 포함)을 보내던 문제 → 로그인 쿠키와 같은 출처 확인을 요구.
- `/settings`가 입금 안내(계좌 등)를 비로그인 방문자에게도 주던 문제 → 로그인한 회원에게만.
- 기본/예시 `SECRET_KEY`로 실행되면 누구나 로그인 토큰을 위조할 수 있던 문제 → 임시 랜덤 키로 대체하고 경고(재시작 시 로그아웃되므로 `.env`에 진짜 키를 설정할 것).
- 보안 헤더(nosniff, frame deny, referrer, permissions) 추가. 가입은 IP당 시간당 10회, 로그인 실패는 계정 단위 상한(40회/10분) 추가.
- SQLite WAL + busy_timeout, `/healthz`, Docker HEALTHCHECK, 온라인 백업 스크립트(`scripts/backup_db.py`).
- 회원에게 DB 오류 원문이 나가던 두 곳 정리. 비밀번호 최소 길이 6자로 통일.

운영자가 결정·설정해야 하는 것
- `SECRET_KEY`를 반드시 설정. 백업은 cron으로 `python scripts/backup_db.py`를 매일 실행하고 결과를 서버 밖에도 복사.
- 접속 IP는 `X-Forwarded-For`의 마지막 값을 쓴다. 리버스 프록시(Cloudflare, nginx 등) 뒤에서만 안전하다. 8000 포트를 직접 인터넷에 열면 IP 제한을 우회할 수 있다(계정 단위 상한이 보완하지만 그 계정은 10분간 잠길 수 있다).
- 로그인·가입 제한은 메모리에 저장돼 서버를 재시작하면 초기화된다. 워커는 1개로 유지(쓰기 락도 프로세스 단위).
- CSP(콘텐츠 보안 정책) 헤더는 화면 깨짐 위험이 있어 넣지 않았다. 필요하면 별도로 점검 후 추가.
- 관리자 계정 비밀번호가 `ADMIN_PASSWORD`(.env)로 정해진다. 길고 고유한 값을 사용.
